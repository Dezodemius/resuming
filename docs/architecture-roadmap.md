# Архитектурная дорожная карта

Что осталось за рамками ветки `review/architecture-cleanup` — намеренно.
Перечисленное ниже требует диффа, который нельзя провести параллельно с
другими правками `main.py`, поэтому здесь план, а не код: этапы, порядок,
риски и то, чем каждый этап проверяется.

Документ не про «сделать красиво». Каждый пункт — уже сработавший или
близкий к срабатыванию источник ошибок; для каждого указано, чем именно он
уже стоил или может стоить.

---

## 1. Разделение `main.py` на модули

**Сейчас.** ~2900 строк в одном файле: транспорт (роуты), доменная логика
(списания, лимиты, разбор ответа модели), интеграции (Робокасса, OAuth, SMTP,
Ollama) и MCP-сервер вперемешку. CLAUDE.md прямо предписывает не читать файл
целиком — это верный признак, что размер уже мешает работать.

**Почему это дорого.** Два человека (или два агента) не могут править файл
одновременно без конфликтов. Именно поэтому эта ветка и не делает распил.

**План.** По одному модулю за раз, каждый — отдельный PR, между PR-ами `main`
остаётся зелёным.

| Шаг | Что выносим | Куда | Почему первым/последним |
|---|---|---|---|
| 1 | `_deduct`, `_refund`, `_is_pro`, `_ensure_resume_capacity`, `PRO_FAIR_USE`-квота | `billing.py` | Чистые функции над `db`, транспорта не касаются. Самая ценная часть: здесь деньги |
| 2 | `call_ai`, `_parse_ai`, `_looks_like_injection`, `_looks_like_honest_json_attempt`, `_flag_abuse` | `ai.py` | Тоже без транспорта; `prompts.py` уже отдельно |
| 3 | Робокасса: подпись, чек, `OpStateExt`, разбор вебхука | `payments.py` | Много внешнего контракта, тесты уже есть |
| 4 | OAuth-провайдеры | `oauth.py` | См. пункт 2 ниже — выносить надо уже объединённым |
| 5 | Роуты по группам (`routes/`) через `APIRouter` | `routes/*.py` | Последним: к этому моменту в хендлерах остаётся только транспорт |

**Риски.** Тесты и `monkeypatch` обращаются к именам как к `main.*`
(`monkeypatch.setattr(main, "call_ai", …)`). Пока роуты живут в `main`,
`from billing import _deduct` сохраняет имя в пространстве `main` и подмена
продолжает работать; на шаге 5 это перестанет быть верным, и тесты надо будет
переводить на реальный модуль. Делать это заранее, отдельным коммитом.

**Чем проверяется.** `pytest tests/ -q` без правок тестов на шагах 1–4;
`behave`; мутационный гейт на вынесенных функциях (они перестают быть
декорированными — см. пункт 5, покрытие только вырастет).

## 2. Три OAuth-колбэка — одна процедура

**Сейчас.** `auth_yandex_callback`, `auth_vk_callback`, `auth_mailru_callback`
— ~70 строк каждый, различаются URL-ами провайдера, именем cookie для `state`
и тем, из какого поля ответа доставать email/uid/имя. Всё остальное —
дословные копии: проверка `state`, обработка отказа, обмен кода, отсутствие
email, `_resolve_oauth_user`, обновление `display_name`, создание сессии,
редирект `/settings?linked=…` против `/new?login=success`.

**Почему это дорого.** Правка «на всякий случай» в одном колбэке молча не
приезжает в два других. Ровно эта форма расхождения уже стоила проекту
миграции №4 (`oauth_identities`): привязка по email вместо id провайдера
заводила один аккаунт дважды.

**План.** Описание провайдера — данными, ход входа — одной функцией:

```python
_OAUTH_PROVIDERS = {
    "yandex": OAuthProvider(authorize_url=…, token_url=…, userinfo=…,
                            state_cookie="ya_state", extract=_yandex_identity),
    …
}
```
плюс `_oauth_finish(request, provider, uid, email, name)` — то, что после
получения identity одинаково у всех троих.

**Не делать в этой ветке** ещё и потому, что параллельно идёт
security-ревью, и колбэки — его прямая территория. Объединять надо **после**
того, как его правки приземлятся, иначе исправление уедет в одну копию.

**Чем проверяется.** `tests/test_oauth_linking.py` уже покрывает первый вход,
повторный вход, привязку к существующему аккаунту и отвязку — их достаточно,
если прогнать по всем трём провайдерам параметризацией.

## 3. Авторизация хендлера — зависимостью, а не тремя строками

**Сейчас.** 18 мест повторяют
```python
user = await get_current_user(request)
if not user:
    raise HTTPException(401, …)
```
причём текст различается: «Требуется авторизация» (6 раз), «Войдите в
аккаунт» (9 раз), голый `HTTPException(401)` (3 раза, клиент получает
«Unauthorized» по-английски).

**План.** `async def require_user(request) -> dict` и
`user: dict = Depends(require_user)` в сигнатуре. Диффом это 18 изменённых
сигнатур — то есть тот же конфликт, что и в пункте 1, поэтому вместе с ним.

**Побочная выгода.** Один текст ответа на всё приложение; сейчас фронту
приходится различать три формулировки одного и того же состояния.

## 4. Один контур — одно имя проекта у compose

**Сейчас.** `deploy/docker-compose.prod.yml` объявляет `name: resuming`,
staging — `resuming-staging`, dev — `resuming-dev`. Корневой
`docker-compose.yml` не объявляет ничего и берёт имя каталога — то есть тоже
`resuming`. Совпадают и имя тома (`resuming_app_data`), и `container_name`
(`resuming-app`).

**Чем это грозит.** CLAUDE.md предупреждает, что запуск корневого compose на
app-01 займёт 80-й порт и уронит соседние сайты. Но до порта дело даже не
дойдёт: контейнер и том столкнутся с боевыми по имени.

**Почему не сделано здесь.** Добавить `name:` в корневой compose — значит
сменить имя тома у всех, кто уже поднимал проект локально: их база «исчезнет»
(останется в старом томе). Это требует строки в README и осознанного решения
владельца, а не тихой правки в чужом PR.

**План.** `name: resuming-local` + `container_name: resuming-local-app` в
корневом compose, абзац в `deploy/README.md` о том, как перенести том
(`docker run --rm -v resuming_app_data:/from -v resuming-local_app_data:/to …`).

## 5. HTTP-слой вне мутационного гейта

**Сейчас.** mutmut не мутирует декорированные функции, поэтому все `@app.get`
/`@app.post`-хендлеры под гейт не попадают вовсе — `tools/mutation_diff.py`
даже печатает об этом отдельное пояснение. Гейт жёсткий (любой выживший
мутант — красная сборка), но проверяет он не то, что думает читатель зелёной
галочки.

**Как выяснилось на практике.** Вынос общего хода генерации в
`_run_generation` (эта ветка) втянул под гейт кусок, который раньше в него не
попадал, — и сразу дал 56 выживших мутантов. Это не регрессия, а измерение:
синхронная генерация всё это время была покрыта заметно хуже асинхронной,
и увидеть это было нечем. После десяти новых тестов — ноль выживших.

**План (в порядке отдачи).**
1. Продолжать выносить тело хендлеров в обычные функции — не ради красоты, а
   потому что это единственный способ завести туда гейт. Пункт 1 делает это
   попутно.
2. Дописать в `tools/mutation_diff.py` предупреждение, когда **все** цели
   диффа оказались недекорированными: сейчас такой прогон печатает «проверять
   нечего» и возвращает 0 — по логу это неотличимо от «всё хорошо».
3. Рассмотреть `--scope files` для файлов, где доля хендлеров велика.

## 6. Расширение набора правил линтера

`ruff.toml` (добавлен в этой ветке) фиксирует ровно тот набор, что
проверялся раньше: `E4/E7/E9 + F`. На ruff 0.16 тот же код даёт 80 замечаний
по правилам, которых в закреплённой 0.8 в умолчании не было.

Кандидаты, до которых близко, — по одному правилу за коммит:

| Правило | Замечаний | Комментарий |
|---|---|---|
| `I` (isort) | 13 | Механическая правка, но затрагивает шапки 13 файлов — конфликтует со всем подряд |
| `UP` (pyupgrade) | ~26 | `Optional[X]` → `X \| None`, `List` → `list`. Безопасно, но шумно |
| `BLE001` (blind except) | 17 | **Самое ценное**: каждый `except Exception` стоит разобрать глазами, часть из них глушит и то, что глушить не надо |
| `DTZ005` | 2 | `datetime.now()` без tz — в `_save_resume` и рядом; стоит посмотреть отдельно |
| `S110` (try/except/pass) | 2 | Тот же разговор, что и `BLE001` |

## 7. Мелочи, до которых не дошли руки

- **`templates/_footer.html`** — легаси-подвал с инлайновыми стилями, остался
  только у `/admin`. Дублирует список ссылок из `_app_footer.html`, но без
  реквизитов продавца. Заменить включением общего подвала и удалить.
- **`deploy/.env.staging.example`** не содержит `AI_API_KEY`, хотя стенд
  ходит на внешний OpenAI-совместимый провайдер ровно так же, как прод.
  Поднятый по этому шаблону стенд получит 401 от провайдера.
- **`redesign/`** (440 КБ макетов и скриншотов) и `docs/superpowers/` лежат в
  репозитории без ссылок из кода. В образ они больше не едут
  (`.dockerignore`), но вопрос «это ещё нужно?» остаётся к владельцу.
- **`EXPECTED_TABLES` в `tests/test_db.py`** проверяет вхождение (`<=`) и не
  знает о пяти из двенадцати таблиц. Полный слепок теперь живёт в
  `tests/test_db_schema.py`; старую константу можно убрать, когда рядом не
  будет параллельных веток.
- **Общий `login_as` для тестов.** `_login` продублирован дословно в
  `test_api.py`, `test_landing.py` и (теперь) `test_generation_flow.py`, ещё
  три файла заводят сессию по-своему. Вынести в `tests/helpers.py` — правка
  на шесть файлов, то есть максимум конфликтов при минимуме пользы прямо
  сейчас.
